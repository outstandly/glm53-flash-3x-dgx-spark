## E3 grouped fat-expert MoE (step 11), 2026-09-14 10:30

Same three boxes and config as "this fork" above, plus `EXL3_FAT_GROUPED=1 EXL3_TEMP_ROWS_FUSED=32`. Rank 0 log:
`configured_tier=grouped effective_tier=grouped tier_reason=grouped_ok sym_fat_moe=1 grouped_eligible=1`.
KV pool 1,778,242 tokens (was 1,786,610); MemAvailable 9 / 12 / 13 GB (unchanged).

Cold prefill, `scripts/prefill-bench.py` (unique random prompt per run so the prefix cache cannot hit,
`max_tokens=1`, wall time of the whole request; two runs per size):

| Prompt tokens | Before E3 | With E3 | Δ |
|---:|---:|---:|---:|
| ~12.5k | 1,244 / 1,199 tok/s | 1,163 (first call, kernel JIT) / 1,637 tok/s | +34 % (warm) |
| ~50k | 1,229 / 1,236 tok/s | 1,564 / 1,763 tok/s | +27–43 % |
| ~160k | 1,210 tok/s (132.6 s) | 1,615 tok/s (99.7 s) | +33 % |

The first prefill after boot pays the E3 kernel warm-up once. Decode is not touched by E3 (the grouped tier
only runs on prefill-sized steps); decode check below.

Decode check (Mia's `tests/bench_decode.py --structured`, count-1-to-200, temp 0, thinking off, model id
patched to `glm-5.3-flash`): 85.7 tok/s on the first run with DFlash2 accepting 7/7, i.e. the same as the
pre-E3 single-stream figure (88 tok/s). The two later runs (68–71) and the prose prompt (34 tok/s, accept 0.33)
overlapped with two other users' sessions, so they are not a clean measurement. As expected, E3 changed nothing on decode.
